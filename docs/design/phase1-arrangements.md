## User-visible choices proposed for approval

1. Copy syntax remains role=arrange, copy=<part name>, optional instrument/octave/transpose. Pitched melody/bass/chords/arrange and legacy notes with omitted role can be sources. Rhythm/drums/offbeat_tick are explicitly rejected. Copy chains are allowed. Unknown/self/cyclic references and duplicate names fail regardless of selection. Counter sources are explicitly named using new source=<part name> with accent=counter and must be direct role=melody parts (phrases/grid or absolute bars); no implicit first-melody selection. source is allowed ONLY with accent=counter, not phrase_start or other parts. This resolves C's optional phrase_start source proposal in favor of B's no-source design.
2. Copy preserves compiled onset, duration and velocity, applying only its own relative octave, transpose, then common octave range correction. Source pitches already include source pitch transforms. Instrument alone is inherited if absent; explicit instrument overrides, null fails. Source mix settings, sections and DSP settings are never inherited. Source mute does not silence a copy. An explicit copy.velocity is rejected, avoiding a setting silently ignored or an unapproved override. Destination volume/pan etc remain independent. Copy uses source events already restricted by source selection. Destination selection accepts events whose original onset lies in a selected occurrence, clips duration at that occurrence/song end, and never reattacks a sustaining note that started before a selected occurrence. It does not split/revoice at harmony boundaries. Source-generated hard windows propagate as metadata and intersect destination windows.
3. phrase_start uses existing accent syntax with required pitched instrument, one note at each selected expanded occurrence start, not every bar or rest. No finer phrase boundaries exist. Pitch is max(current harmony.pitches)+12, duration .5 beats clipped to harmony/occurrence/song end, base velocity90 times1.2=108 by default. Thus inversion/additional tones affect the chosen actual top chord tone. A' references A material but has its own occurrence start. No source field.
4. offbeat_tick uses accent=offbeat_tick, existing kit/voices representation and real hat only. Omitted kit means hat; supplied kit must include hat; no new aliases or fake sampled voice. instrument is rejected for this drum generator. Within-bar positions: 4/4 .5,1.5,2.5,3.5; 3/4 .5,1.5,2.5; 6/8 .75,2.25 (halfway between dotted-quarter pulses). Default velocity95*.8=76; no duration/gate in drum tuples. Existing chords.offbeat keeps its old behavior.
5. counter is automatic response only, using {role:arrange,instrument:kalimba,accent:counter,source:melody}. Occupancy is union of source compiled [onset,onset+duration) BEFORE gate/swing/jitter/strum/release/reverb. Gate articulation gaps do not become compositional rests; chords/holds/overlaps/adjacent notes occupy their union. Source selection and destination selection intersect by exact occurrence name; excluded source occurrences are not rests, but a selected all-rest phrase is a real rest. Source mute is mix-only. In every gap split at bar/harmony/occurrence boundaries, emit at segment start then every .5 beats, only while >=.5 beats remain. Pitch always harmony.root+12, duration .4 beats, velocity90 strong /72 weak by default. No melodic search, alternation, voice leading or wraparound gap. Fractional boundaries restart the local schedule, short fragments are skipped. Pitch octave/transpose/range rules are shared.
6. Independent minimal countermelody is a separate role=arrange pitched part written with existing phrases+grid or absolute bars. It may overlap melody, uses existing direct-note semantics and DSP, and introduces no countermelody flag or automatic composition. D must test/document this separately; counter alone does not establish countermelody support.
7. All three meters supported by new generators: 4/4=4 quarter beats,3/4=3,6/8=3. Strong beats0/2,0,0/1.5. Unsupported meters fail before audio even empty selection. Exact sections matches A independently of A', repeated A selects all A occurrences. No variation inferred.

## Integration decision and current state

A second event representation or renderer would duplicate DSP and risk old audio. The implementation therefore uses the accepted A/B/C APIs and existing tuples. `bgm/arrangement.py` resolves both reference fields before compilation, makes separate effective part dictionaries, validates direct notation even with empty selection, and compiles dependency-first. `render.compile_song` adds `effective_parts` and parallel `event_metadata` only for songs using copy/accent/source. Old compiled objects remain unchanged. Independent directly notated arrange parts retain their direct DSP path and can overlap melody; they are tested separately from generated counter responses.

Metadata retains each original event's identical-event ordinal, ordered original tone indices and optional hard window. Copy filters metadata by original onset without matching tuples by equality, so simultaneous duplicates retain identity. Copy chains intersect windows with destination occurrence/song; they do not add harmony splits. Counter windows are the intersection of original written-duration gaps, bar, harmony, occurrence and song. Gate and swing never create counter rests. Destination transforms happen once in the compiler, destination DSP once in the renderer. Release and reverb remain separate from held duration.

New hashes include the effective destination instrument, actual compiled events and metadata plus existing audio settings. Source mix/DSP and unrelated parts do not enter dependent hashes. Engine0.2 and chord_pattern_dsp=1 remain unchanged. No arrangement-only revision is needed: previously ignored copy/phrase_start parts produced empty events, whereas the integrated hash includes actual events/windows/effective instrument. The final helper warms those real baseline738b980 caches and requires only copy/phrase_start invalidation, exact unchanged source arrays and normal/force equality. Existing hashes and audio are compared exactly against738b980; no old-audio rebaseline is authorized.

See [Architecture](../dev/Architecture.md) for the data flow and [BuildAndTest](../dev/BuildAndTest.md) for the repository-only final helper and retained evidence. Before means the same example minus generated copy/accent parts; the independently written countermelody remains on both sides. Numeric tests cover all meters, fractional harmony, exact selections, all-rest phrases, references, transform/range rules, hard bounds, event identity and early CLI failures. Full-array regression covers force, interleaving, unrelated insertion, partial caches, separate processes, key-only edits and source note/instrument dependencies.

## Musical intent, limitations and remaining scope

Copy provides an octave/unison layer while preserving rhythm and ordered voicing. Phrase-start decorates an expanded occurrence using the actual highest chord tone; it does not analyze melodic phrases. Tick marks the approved metrical offbeats. Counter fills written rests with repeated harmony roots, without melodic search, voice leading or a wraparound response. These are deterministic minimal initial rules, not validated musical recommendations. An independent composed countermelody is directly written with phrases/grid or absolute bars; counter alone does not implement composition of one.

Spec3.6's listed bass/chord/rhythm/accent patterns now have implementations, subject to their documented meter and real-catalog requirements. Copy and a separately tested direct countermelody are also integrated. This does not establish the full specification or phase1 as complete: variation is next, followed by three templates and phase1 listening. No user listening request is made in this batch. At that phase boundary, ask whether octave layering masks the melody, phrase-start accents suit the form, ticks support6/8 pulses, root responses become monotonous or overlap perceived melody tails, the independent line clashes, and the seam/balance are acceptable. Subjective listening and actual sampled swing_ride/bongo WAVs remain unverified. MIDI, usage mixes, a new UI, full automatic composition and additional voice leading are outside this implementation.
